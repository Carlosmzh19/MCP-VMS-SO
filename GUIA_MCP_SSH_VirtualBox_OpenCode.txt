GUIA COMPLETA: MCP DE ADMINISTRACION SSH PARA DOS MAQUINAS VIRTUALES EN VIRTUALBOX
======================================================================================

Version de la guia: 1.0
Fecha: 02-09-2026
Plataforma principal: Windows (PC host)
Cliente IA: OpenCode
Protocolo: Model Context Protocol (MCP)
Implementacion propuesta: Python + MCP Python SDK v2 + OpenSSH nativo de Windows
Objetivo: permitir que OpenCode use un MCP local en el host para ejecutar operaciones
sobre dos VMs mediante SSH.

======================================================================================
0. RESUMEN DE TU SITUACION ACTUAL
======================================================================================

Tus conexiones manuales ya funcionan:

    ping 192.168.10.10
    ping 192.168.10.20

    ssh -i "$env:USERPROFILE\.ssh\id_rsa" usuariolocal@192.168.10.10
    ssh -i "$env:USERPROFILE\.ssh\id_rsa" Administrador@192.168.10.20

Por lo tanto, NO necesitas que el MCP "resuelva" la red de VirtualBox ni que instales
el MCP dentro de las VMs.

La arquitectura recomendada es:

    +--------------------------------------------------------------+
    |                         PC HOST WINDOWS                      |
    |                                                              |
    |   OpenCode                                                  |
    |      |                                                       |
    |      | MCP stdio                                             |
    |      v                                                       |
    |   virtualbox-ssh-mcp (Python)                               |
    |      |                                                       |
    |      | llama a ssh.exe / scp.exe del host                    |
    |      |                                                       |
    +------+---------------------------+--------------------------+
           |                           |
           | SSH                       | SSH
           v                           v
    +-------------+             +----------------+
    | VM 1        |             | VM 2           |
    | Linux       |             | Windows        |
    | 192.168.10.10|            | 192.168.10.20  |
    | SSH : 22    |             | OpenSSH : 22   |
    | usuariolocal|             | Administrador  |
    +-------------+             +----------------+

La ventaja de esta arquitectura es que OpenCode solamente conoce herramientas MCP.
El MCP se encarga de traducir las peticiones del agente a comandos SSH.

IMPORTANTE:
- No se abre un nuevo servidor HTTP del MCP.
- No se expone el MCP a la red.
- OpenCode ejecuta el MCP localmente.
- El MCP usa el mismo OpenSSH del host que ya probaste manualmente.
- La clave privada id_rsa se queda en el host y NO se copia al código del MCP.
- Para empezar, no dependas de Paramiko/AsyncSSH: usar ssh.exe reduce variables y
  reutiliza exactamente la ruta de autenticacion que ya funciona.

======================================================================================
1. POR QUE PODIAS TENER TIMEOUT EN OPENCODE
======================================================================================

Hay varias capas de timeout que no deben confundirse:

1) Timeout de conexion SSH:
   ssh.exe puede tardar al conectar.

2) Timeout del proceso del MCP:
   Python puede quedarse esperando a ssh.exe.

3) Timeout de OpenCode para descubrir/cargar herramientas MCP:
   La documentacion actual de OpenCode indica un timeout local MCP por defecto de 5000 ms
   para la obtencion de herramientas. Se puede sobrescribir mediante "timeout".
   Este timeout NO debe interpretarse automaticamente como un limite universal para
   cualquier comando remoto.

4) Tiempo del comando remoto:
   un "systemctl status", "journalctl", "Get-WinEvent", una instalacion de paquetes,
   etc. puede tardar bastante mas que un simple "echo OK".

La solucion es controlar cada capa por separado:

- SSH: ConnectTimeout razonable (por ejemplo 10 s).
- SSH keepalive: ServerAliveInterval/CountMax.
- MCP: timeout configurable para el servidor MCP.
- Herramientas Python: timeout propio para cada comando (por ejemplo 60 s).
- Para tareas largas, definir posteriormente una herramienta asyncrona de jobs.

NO recomiendo poner ConnectTimeout enorme. Si la VM esta apagada, el agente debe saber
rapidamente que no puede conectar.

3. CONFIGURACION DE RED EN VIRTUALBOX
======================================================================================

Tu red ya funciona, así que NO cambies nada solo por seguir esta guia.

La recomendacion para un laboratorio es:

    Adaptador 1 -> NAT
        Permite salida a Internet de la VM cuando haga falta.

    Adaptador 2 -> Host-Only
        Permite comunicacion:
            HOST <-> VM1
            HOST <-> VM2
            VM1  <-> VM2

VirtualBox documenta Host-Only como una red donde el host y las VMs pueden comunicarse
como si estuvieran conectados a un switch virtual, sin que esa interfaz tenga que
estar expuesta a la red fisica.

Si actualmente tus IP 192.168.10.10 y 192.168.10.20 funcionan desde el host, puedes
mantener la configuracion existente.

VERIFICACION DESDE HOST:

    ping 192.168.10.10
    ping 192.168.10.20

VERIFICACION DE PUERTO 22:

    Test-NetConnection 192.168.10.10 -Port 22
    Test-NetConnection 192.168.10.20 -Port 22

El resultado importante es:

    TcpTestSucceeded : True

======================================================================================
4. CONFIGURACION DEL CLIENTE SSH DEL HOST
======================================================================================

Esta parte es MUY importante.

En lugar de que el MCP conozca:

    IP
    usuario
    ruta de clave

vamos a crear alias SSH:

    linux-vm
    windows-vm

El archivo esta en:

    %USERPROFILE%\.ssh\config

Si no existe, crealo.

CONTENIDO PROPUESTO:

    Host linux-vm
        HostName 192.168.10.10
        User usuariolocal
        IdentityFile ~/.ssh/id_rsa
        IdentitiesOnly yes
        PreferredAuthentications publickey
        PasswordAuthentication no
        ConnectTimeout 10
        ServerAliveInterval 15
        ServerAliveCountMax 3
        StrictHostKeyChecking accept-new

    Host windows-vm
        HostName 192.168.10.20
        User Administrador
        IdentityFile ~/.ssh/id_rsa
        IdentitiesOnly yes
        PreferredAuthentications publickey
        PasswordAuthentication no
        ConnectTimeout 10
        ServerAliveInterval 15
        ServerAliveCountMax 3
        StrictHostKeyChecking accept-new

NOTAS:

- IdentityFile no contiene la clave; solo indica donde esta.
- IdentitiesOnly yes evita que el cliente intente claves adicionales innecesarias.
- PasswordAuthentication no evita que el agente quede esperando una contraseña.
- ConnectTimeout 10 evita esperas excesivas.
- ServerAlive* ayuda a detectar conexiones muertas.
- StrictHostKeyChecking accept-new acepta una nueva clave de host, pero no deberia
  aceptar silenciosamente una clave cambiada.

COMPROBAR LOS ALIAS:

    ssh -G linux-vm
    ssh -G windows-vm

COMPROBAR SSH SIN INTERACCION:

    ssh -o BatchMode=yes linux-vm "echo SSH_OK_LINUX"
    ssh -o BatchMode=yes windows-vm "echo SSH_OK_WINDOWS"

Tambien puedes usar:

    ssh linux-vm
    ssh windows-vm

Si estos dos comandos funcionan, la capa SSH esta lista.

======================================================================================
5. SSH-AGENT EN WINDOWS
======================================================================================

Si tu id_rsa NO tiene passphrase:
- El MCP puede usarla directamente.

Si tu id_rsa TIENE passphrase:
- Para evitar que un MCP automatizado se bloquee esperando una pregunta de contraseña,
  puedes usar ssh-agent del host.

Verificar:

    Get-Service ssh-agent

Configurar inicio automatico (PowerShell como Administrador):

    Get-Service ssh-agent | Set-Service -StartupType Automatic
    Start-Service ssh-agent

Agregar la clave:

    ssh-add "$env:USERPROFILE\.ssh\id_rsa"

Verificar:

    ssh-add -l

IMPORTANTE:
Usar ssh-agent mejora la automatizacion cuando la clave tiene passphrase.
No escribas la passphrase dentro del codigo Python.

6. CONFIGURACION DE LA VM LINUX (192.168.10.10)
======================================================================================

Asumimos:

    IP:       192.168.10.10
    Usuario:  usuariolocal
    Puerto:   22

Ya tienes SSH funcional, por lo que solo debes asegurarte de que el servidor SSH
permanezca disponible al reiniciar.

COMPROBAR:

    sudo systemctl status ssh
    sudo systemctl enable ssh
    sudo systemctl start ssh

En distribuciones donde el servicio se llama sshd:

    sudo systemctl status sshd

COMPROBAR QUE ESCUCHA EN PUERTO 22:

    sudo ss -lntp | grep :22

FIREWALL:

Si usas UFW:

    sudo ufw status
    sudo ufw allow 22/tcp

Es preferible permitir el puerto SSH solo desde la red del laboratorio cuando sea
posible.

EJEMPLO CON SUBRED 192.168.10.0/24:

    sudo ufw allow from 192.168.10.0/24 to any port 22 proto tcp

No ejecutes un "ufw allow 22/tcp" indiscriminadamente si esta VM queda expuesta a
otra red.

CLAVE PUBLICA:

El servidor debe tener la clave publica del host en:

    ~/.ssh/authorized_keys

Comprobar:

    ls -la ~/.ssh
    cat ~/.ssh/authorized_keys

Permisos Linux recomendados:

    chmod 700 ~/.ssh
    chmod 600 ~/.ssh/authorized_keys

El propietario debe ser el usuario correcto:

    chown -R "$USER:$USER" ~/.ssh

PRUEBA FINAL DESDE HOST:

    ssh -o BatchMode=yes linux-vm "whoami"
    ssh -o BatchMode=yes linux-vm "hostname"
    ssh -o BatchMode=yes linux-vm "uname -a"

======================================================================================
8. CLAVE SSH PARA EL USUARIO ADMINISTRADOR DE WINDOWS
======================================================================================

ESTA PARTE ES ESPECIAL EN WINDOWS.

Microsoft documenta que para usuarios pertenecientes al grupo Administrators,
con la configuracion predeterminada de OpenSSH, el archivo de claves autorizadas
puede ser:

    C:\ProgramData\ssh\administrators_authorized_keys

y no necesariamente:

    C:\Users\Administrador\.ssh\authorized_keys

Comprobar si Administrador pertenece a Administrators:

    net user Administrador

o:

    Get-LocalGroupMember -Group "Administrators"

Si la cuenta es administrativa, comprobar:

    Test-Path "$env:ProgramData\ssh\administrators_authorized_keys"

La clave publica del HOST debe estar en ese archivo.

Puede verse como:

    Get-Content "$env:ProgramData\ssh\administrators_authorized_keys"

CONFIGURACION DE ACL RECOMENDADA POR MICROSOFT:

En PowerShell elevado en la VM Windows:

    icacls.exe "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

En sistemas Windows localizados donde el nombre "Administrators" pueda diferir,
puede utilizarse el SID del grupo:

    *S-1-5-32-544

La idea es que solo SYSTEM y Administrators tengan acceso al archivo.

======================================================================================
9. CONFIGURAR POWERSHELL COMO SHELL DE OPENSSH EN WINDOWS
======================================================================================

Esto NO es obligatorio para que SSH funcione.

Pero para un MCP orientado a administracion Windows es recomendable porque hace que:

    ssh windows-vm "Get-Service sshd"

ejecute PowerShell de forma consistente.

Microsoft documenta que el shell inicial de OpenSSH en Windows es normalmente cmd.exe
y que se puede cambiar mediante:

    HKLM:\SOFTWARE\OpenSSH
    DefaultShell

PowerShell:

    $NewItemPropertyParams = @{
        Path = "HKLM:\SOFTWARE\OpenSSH"
        Name = "DefaultShell"
        Value = "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe"
        PropertyType = "String"
        Force = $true
    }

    New-ItemProperty @NewItemPropertyParams

Reiniciar:

    Restart-Service sshd

Probar:

    ssh windows-vm '$PSVersionTable.PSVersion'

IMPORTANTE:
Si tu OpenSSH/Windows ya esta configurado y tus comandos remotos funcionan, no cambies
esta parte a ciegas. Primero prueba y solo cambia el shell si quieres comportamiento
PowerShell consistente.

======================================================================================
15. MCP COMPLETO DE PRIMERA VERSION
======================================================================================

Crea:

    server.py

CONTENIDO:

    import base64
    import json
    import logging
    import os
    import platform
    import subprocess
    from pathlib import Path
    from typing import Any

    from mcp.server import MCPServer


    BASE_DIR = Path(__file__).resolve().parent
    MACHINES_FILE = BASE_DIR / "config" / "machines.json"
    LOG_DIR = BASE_DIR / "logs"
    LOG_DIR.mkdir(parents=True, exist_ok=True)

    LOG_FILE = LOG_DIR / "mcp.log"

    logging.basicConfig(
        level=logging.INFO,
        handlers=[
            logging.FileHandler(LOG_FILE, encoding="utf-8"),
            logging.StreamHandler(),
        ],
        format="%(asctime)s | %(levelname)s | %(message)s",
    )

    logger = logging.getLogger("virtualbox-ssh-mcp")

    SSH_TIMEOUT_DEFAULT = 60
    SSH_CONNECT_TIMEOUT = 10

    mcp = MCPServer(
        "virtualbox-ssh-mcp",
        description="MCP local para administrar VMs mediante SSH desde el host."
    )


    def load_config() -> dict[str, Any]:
        with MACHINES_FILE.open("r", encoding="utf-8") as file:
            return json.load(file)


    def get_machines() -> dict[str, Any]:
        config = load_config()
        machines = config.get("machines", {})

        if not isinstance(machines, dict) or not machines:
            raise RuntimeError("No hay maquinas configuradas en machines.json")

        return machines


    def get_machine(machine: str) -> dict[str, Any]:
        machines = get_machines()

        if machine not in machines:
            available = ", ".join(sorted(machines.keys()))
            raise ValueError(
                f"Maquina desconocida: {machine}. Disponibles: {available}"
            )

        return machines[machine]


    def run_process(
        args: list[str],
        timeout: int = SSH_TIMEOUT_DEFAULT,
    ) -> dict[str, Any]:
        logger.info("Ejecutando proceso: %s", args)

        try:
            completed = subprocess.run(
                args,
                capture_output=True,
                text=True,
                encoding="utf-8",
                errors="replace",
                timeout=timeout,
                check=False,
            )

            return {
                "ok": completed.returncode == 0,
                "return_code": completed.returncode,
                "stdout": completed.stdout,
                "stderr": completed.stderr,
                "command": args,
            }

        except subprocess.TimeoutExpired as exc:
            logger.error("Timeout ejecutando proceso: %s", args)

            return {
                "ok": False,
                "return_code": -1,
                "stdout": exc.stdout or "",
                "stderr": (
                    (exc.stderr or "")
                    + f"\nProceso excedio el timeout de {timeout} segundos."
                ),
                "command": args,
                "timeout": True,
            }

        except FileNotFoundError as exc:
            logger.exception("Executable no encontrado")
            return {
                "ok": False,
                "return_code": -1,
                "stdout": "",
                "stderr": str(exc),
                "command": args,
                "error": "Executable no encontrado. Verifica PATH.",
            }

        except Exception as exc:
            logger.exception("Error ejecutando proceso")
            return {
                "ok": False,
                "return_code": -1,
                "stdout": "",
                "stderr": str(exc),
                "command": args,
                "error": type(exc).__name__,
            }


    def ssh_args(host: str, command: str) -> list[str]:
        return [
            "ssh.exe",
            "-o", f"ConnectTimeout={SSH_CONNECT_TIMEOUT}",
            "-o", "BatchMode=yes",
            host,
            command,
        ]


    def scp_destination(host: str, remote_path: str) -> str:
        return f"{host}:{remote_path}"


    def clean_output(result: dict[str, Any], max_chars: int = 20000) -> dict[str, Any]:
        result["stdout"] = result.get("stdout", "")[-max_chars:]
        result["stderr"] = result.get("stderr", "")[-max_chars:]
        return result


    @mcp.tool()
    def list_machines() -> str:
        """Lista las VMs que este MCP permite administrar."""
        machines = get_machines()

        output = []
        for name, data in machines.items():
            output.append({
                "name": name,
                "ssh_host": data["ssh_host"],
                "os": data.get("os", "unknown"),
                "description": data.get("description", ""),
            })

        return json.dumps(output, ensure_ascii=False, indent=2)


    @mcp.tool()
    def test_ssh(machine: str) -> str:
        """
        Comprueba que el host puede autenticarse por SSH contra la VM usando
        el alias configurado en ~/.ssh/config.
        """
        data = get_machine(machine)
        host = data["ssh_host"]

        result = run_process(
            ssh_args(host, "echo MCP_SSH_OK"),
            timeout=20,
        )

        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def run_command(
        machine: str,
        command: str,
        timeout_seconds: int = SSH_TIMEOUT_DEFAULT,
    ) -> str:
        """
        Ejecuta un comando remoto por SSH.

        USO:
        - Linux: comandos bash/shell.
        - Windows: comandos PowerShell si DefaultShell esta configurado como PowerShell.

        IMPORTANTE:
        Esta herramienta otorga control administrativo sobre la VM. Usarla solo
        contra maquinas de laboratorio autorizadas.
        """
        if not command.strip():
            raise ValueError("El comando no puede estar vacio.")

        if timeout_seconds < 1 or timeout_seconds > 600:
            raise ValueError("timeout_seconds debe estar entre 1 y 600.")

        data = get_machine(machine)
        host = data["ssh_host"]

        result = run_process(
            ssh_args(host, command),
            timeout=timeout_seconds,
        )

        result["machine"] = machine
        result["os"] = data.get("os", "unknown")

        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def get_system_info(machine: str) -> str:
        """Obtiene informacion basica del sistema remoto."""
        data = get_machine(machine)
        os_type = data.get("os", "unknown")

        if os_type == "linux":
            command = (
                "echo '--- HOSTNAME ---'; hostname; "
                "echo '--- OS ---'; uname -a; "
                "echo '--- UPTIME ---'; uptime; "
                "echo '--- MEMORY ---'; free -h; "
                "echo '--- DISK ---'; df -h /"
            )
        elif os_type == "windows":
            command = (
                "$ErrorActionPreference='Continue'; "
                "Write-Output '--- COMPUTERNAME ---'; $env:COMPUTERNAME; "
                "Write-Output '--- OS ---'; "
                "Get-CimInstance Win32_OperatingSystem | "
                "Select-Object Caption,Version,BuildNumber; "
                "Write-Output '--- MEMORY ---'; "
                "Get-CimInstance Win32_OperatingSystem | "
                "Select-Object TotalVisibleMemorySize,FreePhysicalMemory; "
                "Write-Output '--- DISK ---'; "
                "Get-PSDrive -PSProvider FileSystem | "
                "Select-Object Name,Used,Free"
            )
        else:
            raise ValueError(f"OS no soportado: {os_type}")

        result = run_process(
            ssh_args(data["ssh_host"], command),
            timeout=30,
        )

        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def get_service_status(machine: str, service: str) -> str:
        """Obtiene el estado de un servicio remoto."""
        if not service.strip():
            raise ValueError("service no puede estar vacio.")

        data = get_machine(machine)
        os_type = data.get("os", "unknown")

        if os_type == "linux":
            command = f"systemctl status {service} --no-pager"
        elif os_type == "windows":
            command = (
                f"Get-Service -Name '{service}' | "
                "Select-Object Name,DisplayName,Status,StartType"
            )
        else:
            raise ValueError(f"OS no soportado: {os_type}")

        result = run_process(
            ssh_args(data["ssh_host"], command),
            timeout=30,
        )

        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def restart_service(machine: str, service: str) -> str:
        """
        Reinicia un servicio remoto.
        Requiere privilegios suficientes en la cuenta SSH.
        """
        if not service.strip():
            raise ValueError("service no puede estar vacio.")

        data = get_machine(machine)
        os_type = data.get("os", "unknown")

        if os_type == "linux":
            command = f"sudo systemctl restart {service}"
        elif os_type == "windows":
            command = f"Restart-Service -Name '{service}' -Force"
        else:
            raise ValueError(f"OS no soportado: {os_type}")

        result = run_process(
            ssh_args(data["ssh_host"], command),
            timeout=45,
        )

        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def get_logs(
        machine: str,
        source: str,
        lines: int = 100,
    ) -> str:
        """
        Obtiene logs de un servicio/fuente.

        Linux:
            source = nombre del servicio para journalctl -u

        Windows:
            source = nombre de un LogName de Windows Event Log,
            por ejemplo: System, Application, Security
        """
        if not source.strip():
            raise ValueError("source no puede estar vacio.")

        if lines < 1 or lines > 1000:
            raise ValueError("lines debe estar entre 1 y 1000.")

        data = get_machine(machine)
        os_type = data.get("os", "unknown")

        if os_type == "linux":
            command = (
                f"journalctl -u {source} -n {lines} "
                "--no-pager --output=short-iso"
            )
        elif os_type == "windows":
            command = (
                f"Get-WinEvent -LogName '{source}' -MaxEvents {lines} | "
                "Select-Object TimeCreated,Id,LevelDisplayName,ProviderName,Message | "
                "Format-List"
            )
        else:
            raise ValueError(f"OS no soportado: {os_type}")

        result = run_process(
            ssh_args(data["ssh_host"], command),
            timeout=60,
        )

        return json.dumps(clean_output(result, 30000), ensure_ascii=False, indent=2)


    @mcp.tool()
    def read_file(
        machine: str,
        remote_path: str,
        max_chars: int = 20000,
    ) -> str:
        """Lee un archivo de texto remoto."""
        if not remote_path.strip():
            raise ValueError("remote_path no puede estar vacio.")

        if max_chars < 1 or max_chars > 100000:
            raise ValueError("max_chars debe estar entre 1 y 100000.")

        data = get_machine(machine)
        os_type = data.get("os", "unknown")

        if os_type == "linux":
            command = f"cat -- '{remote_path}'"
        elif os_type == "windows":
            command = f"Get-Content -Raw -LiteralPath '{remote_path}'"
        else:
            raise ValueError(f"OS no soportado: {os_type}")

        result = run_process(
            ssh_args(data["ssh_host"], command),
            timeout=30,
        )

        return json.dumps(
            clean_output(result, max_chars),
            ensure_ascii=False,
            indent=2,
        )


    @mcp.tool()
    def write_file(
        machine: str,
        remote_path: str,
        content: str,
    ) -> str:
        """
        Escribe un archivo de texto remoto.

        Para evitar problemas de comillas y caracteres especiales, el contenido
        se codifica en base64 localmente antes de enviarlo.
        """
        if not remote_path.strip():
            raise ValueError("remote_path no puede estar vacio.")

        data = get_machine(machine)
        os_type = data.get("os", "unknown")

        encoded = base64.b64encode(content.encode("utf-8")).decode("ascii")

        if os_type == "linux":
            command = (
                f"echo {encoded} | base64 -d | "
                f"sudo tee -- '{remote_path}' > /dev/null"
            )

        elif os_type == "windows":
            command = (
                "$b64='"
                + encoded
                + "'; "
                "$bytes=[Convert]::FromBase64String($b64); "
                "$text=[Text.Encoding]::UTF8.GetString($bytes); "
                f"Set-Content -LiteralPath '{remote_path}' "
                "-Value $text -Encoding UTF8"
            )
        else:
            raise ValueError(f"OS no soportado: {os_type}")

        result = run_process(
            ssh_args(data["ssh_host"], command),
            timeout=30,
        )

        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def upload_file(
        machine: str,
        local_path: str,
        remote_path: str,
    ) -> str:
        """
        Sube un archivo desde el host hacia la VM mediante scp.

        NOTA:
        Los paths de Windows remotos pueden requerir el formato que soporte la
        version de OpenSSH instalada. Para Windows, prueba por ejemplo:
            /C:/Temp/archivo.txt
        """
        local = Path(local_path).expanduser().resolve()

        if not local.exists():
            raise FileNotFoundError(f"No existe: {local}")

        if not local.is_file():
            raise ValueError(f"No es un archivo: {local}")

        data = get_machine(machine)
        host = data["ssh_host"]

        destination = scp_destination(host, remote_path)

        args = [
            "scp.exe",
            "-o", f"ConnectTimeout={SSH_CONNECT_TIMEOUT}",
            "-o", "BatchMode=yes",
            str(local),
            destination,
        ]

        result = run_process(args, timeout=120)
        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def download_file(
        machine: str,
        remote_path: str,
        local_path: str,
    ) -> str:
        """Descarga un archivo desde la VM hacia el host mediante scp."""
        target = Path(local_path).expanduser().resolve()
        target.parent.mkdir(parents=True, exist_ok=True)

        data = get_machine(machine)
        host = data["ssh_host"]

        source = scp_destination(host, remote_path)

        args = [
            "scp.exe",
            "-o", f"ConnectTimeout={SSH_CONNECT_TIMEOUT}",
            "-o", "BatchMode=yes",
            source,
            str(target),
        ]

        result = run_process(args, timeout=120)
        return json.dumps(clean_output(result), ensure_ascii=False, indent=2)


    @mcp.tool()
    def check_reachability(machine: str) -> str:
        """
        Comprueba desde el host si la IP de la VM responde a ping.

        Usa la IP configurada en el alias SSH.
        """
        # Por seguridad y simplicidad, usamos ssh -G para consultar el HostName
        data = get_machine(machine)
        host = data["ssh_host"]

        result = run_process(
            ["ssh.exe", "-G", host],
            timeout=10,
        )

        if not result["ok"]:
            return json.dumps(clean_output(result), ensure_ascii=False, indent=2)

        hostname = ""
        for line in result["stdout"].splitlines():
            if line.lower().startswith("hostname "):
                hostname = line.split(" ", 1)[1].strip()
                break

        if not hostname:
            return json.dumps(
                {
                    "ok": False,
                    "error": "No se pudo determinar HostName desde ssh -G.",
                },
                ensure_ascii=False,
                indent=2,
            )

        ping_result = run_process(
            ["ping.exe", "-n", "1", hostname],
            timeout=10,
        )

        ping_result["machine"] = machine
        ping_result["resolved_host"] = hostname

        return json.dumps(
            clean_output(ping_result),
            ensure_ascii=False,
            indent=2,
        )


    if __name__ == "__main__":
        logger.info("Iniciando virtualbox-ssh-mcp...")
        logger.info("Host OS: %s", platform.platform())
        logger.info("Config: %s", MACHINES_FILE)
        mcp.run()

25. PROBLEMA IMPORTANTE: COMILLAS Y ESCAPADO
======================================================================================

Un MCP que ejecuta shells remotos siempre tiene el problema del quoting.

Linux:

    bash
    systemctl
    grep
    sed
    awk
    pipes
    redireccionamientos

Windows:

    PowerShell
    comillas simples
    comillas dobles
    variables
    pipes

Por eso:

- Las herramientas especificas deben construir comandos controlados.
- run_command debe usarse solo como herramienta general.
- Para paths, preferir herramientas especializadas read_file/write_file.
- Para servicios, usar get_service_status/restart_service.
- Para logs, usar get_logs.

Con esto disminuyes los casos en que el modelo tiene que construir una cadena SSH
compleja.

30. CONTROL DE PERMISOS EN LINUX
======================================================================================

Para el laboratorio, lo ideal es NO utilizar root directamente.

Mejor:

    SSH -> usuariolocal
           |
           +-- sudo para tareas administrativas seleccionadas

Problema:
Si sudo pide password, una herramienta no interactiva se puede bloquear.

Puedes revisar:

    sudo -n systemctl status ssh

Si devuelve un error porque necesita password, el MCP no debe quedarse esperando.

Puedes configurar sudoers de forma granular mediante:

    sudo visudo

y permitir solo comandos concretos.

Ejemplo conceptual:

    usuariolocal ALL=(root) NOPASSWD: /usr/bin/systemctl status ssh
    usuariolocal ALL=(root) NOPASSWD: /usr/bin/systemctl restart ssh

NO uses:

    usuariolocal ALL=(ALL) NOPASSWD: ALL

en un sistema real solo para que el agente sea comodo.

50. ALTERNATIVA: USAR DIRECTAMENTE OPENCODE + SSH
======================================================================================

Existe una alternativa de proyecto comunitario orientado a SSH para OpenCode.

Puede ser util para evaluar si realmente necesitas tu propio MCP.

Pero tu MCP tiene una ventaja importante:
puedes controlar exactamente las herramientas y el comportamiento para TU laboratorio.

Ejemplo:

    "reinicia ssh en la VM Linux"

no requiere que el agente construya manualmente:

    ssh -i ... usuariolocal@192.168.10.10 ...

En su lugar:

    restart_service("linux-vm", "ssh")

Eso reduce complejidad para el agente y hace el sistema mas mantenible.

Eso ofrece mejor contexto al modelo.
